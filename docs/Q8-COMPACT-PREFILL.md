# Compact Q8 prefill optimization on gfx1151

This report records the investigation that removed the need for DS4's optional
9.85--9.91 GiB-per-rank Q8-to-F16 weight cache on the reference two-node
Strix Halo setup. Raw logs and profiler CSVs are kept under the ignored local
`research-results/2026-08-06/raw/q8-cache-research/` tree.

## Result

| Cache-free TP=2 test | Before | After | Change |
|---|---:|---:|---:|
| Same final binary, 10,093-byte prompt, one generated token | 97.50 t/s | 136.18 t/s | +39.7% |
| 10,093-byte prompt, 30 generated tokens | 101.32 / 13.33 t/s | 138.97 / 13.32 t/s | +37.2% prefill |
| Planned memory per rank | 81.18 GiB | 81.18 GiB | 0 GiB persistent delta |

The faster 30-token run generated byte-for-byte identical text. A separate
opt-in cache trace allocated 9.85 GiB on rank 0 and 9.91 GiB on rank 1, printed
the near-99% warning, and measured 130.91 t/s under tracing. The cache-free
token-tiled trace measured 138.26 t/s.

## Actual execution paths

The normal cache-free attention-output projection has two matrix multiplies:

1. Projection A dynamically quantizes the F32 grouped attention heads with
   `quantize_q8_0_f32_kernel`, then runs
   `grouped_q8_0_a_preq_toktile_warp8_kernel<16>`. Each wave owns one output
   row, keeps eight packed weight words in registers, and reuses them across
   16 prompt tokens. The weights and activations remain Q8.
2. Projection B runs `matmul_q8_0_f32_batch_wmma_4w_kernel` for the large
   prefill shapes. It expands only the current Q8 tile into FP16 LDS/register
   storage and consumes it with FP16 WMMA; there is no persistent expansion.

With `DS4_ROCM_ENABLE_Q8_F16_CACHE=1`, cached projection A and the cached part
of B use FP16 hipBLAS GEMMs. The captured cache trace cached 40 of 43 layer
projections; three A calls and part of B still fell back to compact Q8 after
the cache budget was exhausted.

## Where the old gap went

| Coordinator kernel, 43 layers | Original no-cache | Token-tiled no-cache |
|---|---:|---:|
| Q8 projection A | 8.711 s (30.1%) | 1.642 s (8.0%) |
| Activation Q8 quantization | 0.116 s (0.4%) | negligible / unchanged |
| Q8 projection B tile-local WMMA | 2.641 s | 2.532 s |

The old kernel reread every A weight row separately for every prompt token.
Activation quantization was never the material cost. Reusing each packed
weight block for 16 tokens reduced the hot kernel by 81.2% without changing
its storage format or quantization model.

## Native ISA and resources

The original DP4A kernel already lowered to native signed packed integer dots
on gfx1151, so the problem was not missing INT8 hardware selection. The new
kernel's generated ISA contains 128 unrolled `v_dot4_i32_iu8` instructions.

| Kernel | VGPR | SGPR | spills | LDS | private segment |
|---|---:|---:|---:|---:|---:|
| Original per-token DP4A A | 38 | 32 | 0 | 0 | 0 |
| Token-tiled DP4A A | 74 | 36 | 0 | 0 | 0 |

Both launch 256-thread blocks. Token tiling trades additional live
accumulators, and therefore VGPRs, for a 16-fold weight-reuse opportunity.
There are no spills or LDS occupancy constraint. gfx1151's profiler aborted
when the derived occupancy counters were requested, so this report does not
invent a measured occupancy percentage; the compiler resources and kernel
timings above are the reproducible occupancy evidence available on this ROCm
installation.

## llama.cpp issue 21284 mapping

The public gfx1151 work in `ggml-org/llama.cpp#21284` was the correct lead, but
DS4 does not use llama.cpp MMQ. Its individual ideas map as follows:

| llama.cpp change | DS4 finding |
|---|---|
| Select native gfx1151 DP4A | Already present; both source and ISA verified |
| `mmq_x=48` | Not applicable: DS4 has no llama.cpp MMQ tile-x dispatcher |
| `mmq_y=64` | Not applicable: DS4 has no llama.cpp MMQ tile-y dispatcher |
| Four MMQ warps | Not applicable to DS4's wave-per-output-row kernel |
| `roundf` to integer-round intrinsic | Not material here; all activation quantization was 0.4% of the traced run |
| Reduce MMQ VGPR pressure | Original DS4 kernel had 38 VGPRs and zero spills; its loss was repeated weight traffic |

Current llama.cpp upstream has an RDNA3.5 MMQ configuration, and gfx1151 is
compiled through the RDNA3/RDNA3.5 macros that reach
`__builtin_amdgcn_sudot4`. Its current `quantize_mmq_q8_1` still uses
`roundf`. Those facts do not change DS4 dispatch because the two projects have
different matmul implementations.

- https://github.com/ggml-org/llama.cpp/issues/21284

## Alternatives tested

- The already-existing F32 shared-input kernel reached 122.69 t/s in the
  30-token run. It removed activation quantization but remained slower than
  token-tiled DP4A.
- The dormant tile-local Q8-to-FP16 rocWMMA A kernel was correct within its
  expected FP16 conversion error and only 4--8% faster than shared-X in the
  isolated pp128--pp2048 sweep. That ceiling is below 5% end to end.
- A persistent Q8 repack is unjustified: the native dot path accepts the GGUF
  byte order directly, and the winning kernel retains eight packed words in
  registers without shuffles or a duplicate representation.
- rocWMMA/Composable Kernel INT8 integration is unnecessary for this result.
  The verified vector-dot path is already faster than the cached baseline and
  preserves GGUF block scales directly.

## Controls and portability

The optimization is enabled by default for aligned prefill shapes with at
least eight tokens. Decode and non-aligned shapes retain the old kernel. Set
`DS4_ROCM_ATTN_OUT_Q8_A_PREQ_TOKTILE=0` on both ranks for a diagnostic
rollback. The code changes only ROCm compute dispatch and does not inspect or
modify the transport, so Mellanox uses the same generic verbs path as before.
